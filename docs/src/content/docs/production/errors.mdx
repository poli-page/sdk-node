Every failure thrown by the SDK is an instance of `PoliPageError`. The `code` field tells you what went wrong; the `requestId` field is what to quote when filing a support ticket.

## The error class

```ts
import { PoliPageError } from '@poli-page/sdk';

try {
  await client.render.pdf({ project: 'billing', template: 'invoice', data: {} });
} catch (err) {
  if (err instanceof PoliPageError) {
    console.error(err.code, err.requestId, err.message);
  } else {
    throw err;
  }
}
```

## SDK-internal codes

These originate inside the SDK before any HTTP call (or in response to a network-layer failure). They are lowercase, except `DOWNLOAD_FAILED`.

`DOWNLOAD_FAILED` is raised by `downloadPdf()`, `render.pdf` and `render.pdfStream`, which fetch the bytes after the API stored the document. The client `timeout` bounds that download: the whole download for `render.pdf` and `downloadPdf()`, and for `render.pdfStream` the wait for the first byte and each gap between chunks.

## Example

```ts
import { PoliPage, PoliPageError } from '@poli-page/sdk';

const client = new PoliPage({ apiKey: process.env.POLI_PAGE_API_KEY! });

try {
  const pdf = await client.render.pdf({
    project: 'billing',
    template: 'invoice',
    data: { invoiceNumber: 'INV-001' },
  });
  // ...
} catch (err) {
  if (err instanceof PoliPageError && err.code === 'QUOTA_EXCEEDED') {
    // Not retried by the SDK: queue the job until the monthly reset.
    return;
  }
  throw err;
}
```
