---
title: Retries and idempotency
description: How the SDK retries transient failures and how to make your render calls safe to retry.
---

The Poli Page SDK retries transient failures automatically. Every POST carries an `Idempotency-Key` that stays the same across the retries of one call. The API does not deduplicate on it, so a retried render can store a second document (see [Idempotency](#idempotency)).

## Default retry policy

- `network_error`, `timeout`, 5xx responses (such as `503 PUBLISH_IN_PROGRESS`) and 429 responses (such as `RATE_LIMIT_EXCEEDED`) are retried.
- `QUOTA_EXCEEDED` and `OVERAGE_CAP_EXCEEDED` (429) and `STORAGE_ACCESS_DENIED` (502) are **not** retried: they last until the monthly reset or until the bucket access is restored, so the SDK surfaces them at once and `isRetryable()` is `false`.
- Up to `maxRetries` retries (default 2 — three total attempts); after the last one, the last error is thrown.
- Exponential backoff starting at `retryDelay` ms (default 500), doubling each attempt, with a random factor in `[0.5, 1.5)`.
- Honors the `Retry-After` response header when present (integer seconds or an HTTP-date), clamped to 0–30 s, without jitter. `Retry-After-Ms` is ignored.
- `aborted` (caller-cancelled) is never retried. The presigned-URL download is never retried.

## Disabling retries

Set `maxRetries: 0` on the constructor to disable retries entirely.

```ts
const client = new PoliPage({
  apiKey: process.env.POLI_PAGE_API_KEY!,
  maxRetries: 0,
});
```

## Idempotency

Every POST request (`render.*`, `documents.thumbnails`) includes an `Idempotency-Key` header: a lowercase UUID v4 the SDK generates once per call and sends unchanged on every retry of that call. `GET` and `DELETE` requests and the presigned-URL download send none.

The API does not deduplicate on this header. Every `POST /v1/render` that reaches the renderer stores a new document, so a retry after a 5xx raised *after* the document was stored can create a second one. A `503 PUBLISH_IN_PROGRESS` is raised before any render work, so retrying it never duplicates. If a duplicate matters to you, use a client with `maxRetries: 0` for that call and decide yourself, for example by checking with `documents.get` the document id you already saved.

You can supply your own key via `idempotencyKey` on the input, for example to correlate a call in your logs; it is sent as is on every attempt of that call:

```ts
const pdf = await client.render.pdf({
  project: 'billing',
  template: 'invoice',
  data: { invoiceNumber: 'INV-001' },
  idempotencyKey: 'invoice-INV-001-v1',
});
```

## Example

```ts
import { PoliPage } from '@poli-page/sdk';

const client = new PoliPage({
  apiKey: process.env.POLI_PAGE_API_KEY!,
  maxRetries: 4,
  retryDelay: 250,
});

const pdf = await client.render.pdf({
  project: 'billing',
  template: 'invoice',
  data: { invoiceNumber: 'INV-001' },
});
```
