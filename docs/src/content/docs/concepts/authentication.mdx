The Poli Page Node.js SDK authenticates every request with a bearer token. A key belongs to exactly one environment of your organization; the API resolves the environment from the key and renders the project's copy published there.

## API keys

<ApiKeyCallout />

A key is `pp_{env}_{32 lowercase hex}`, where `{env}` is the name of the key's environment (`pp_sandbox_…`, `pp_live_…`, `pp_staging_…`). A full key matches:

```text
^pp_(?=[a-z][a-z0-9-]{0,19}_)[a-z][a-z0-9]*(?:-[a-z0-9]+)*_[0-9a-f]{32}$
```

Standard and service keys share this one format. The SDK passes the key through and does not check its format; the API answers `401 INVALID_API_KEY` to a key it does not accept.

## Environments

| Environment                           | Key            | Watermark | Counted |
| ------------------------------------- | -------------- | --------- | ------- |
| `sandbox` (every org)                 | `pp_sandbox_…` | yes       | no      |
| `live` (every org, deletable on Pro+) | `pp_live_…`    | no        | yes     |
| created on Pro+ (e.g. `staging`)      | `pp_staging_…` | no        | yes     |

"Counted" means the render counts toward the organization's monthly PDF quota. `sandbox` documents expire 30 days after creation. There is no watermark option: a template that wants a watermark outside `sandbox` uses the `poli-watermark` class.

A render uses the project's copy published in the key's environment, so publish your project to that environment before you render it. There is no version to pick and no key renders the draft.

## Passing the key

Pass the key to the client constructor:

```ts
const client = new PoliPage({ apiKey: process.env.POLI_PAGE_API_KEY! });
```

The SDK never reads `process.env.POLI_PAGE_API_KEY` implicitly. You always pass the key in.

## Example

```ts
import { PoliPage } from '@poli-page/sdk';

const client = new PoliPage({
  apiKey: process.env.POLI_PAGE_API_KEY!,
});
```
